# Proposal

## Why

The repository currently tracks large Unity editor caches, logs, local editor settings, Python bytecode, macOS metadata, and the generated WebGL build. These files create noisy diffs and duplicate reproducible local state instead of keeping version control focused on project sources.

## What Changes

- Add a root `.gitignore` for macOS metadata and Python-generated caches, bytecode, test state, and virtual environments.
- Add `UnityClient/.gitignore` for Unity-generated caches, logs, temporary files, local editor settings, and build output.
- Stop tracking existing generated and machine-local files in those categories while preserving their local working copies.
- Keep Unity assets, package manifests, project settings, and source fixtures tracked; require a fresh checkout to build the WebGL client before serving it.
- Do not rewrite Git history; previously committed generated files remain in earlier commits.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. This is a repository-tooling change with no product behavior changes, so specs are intentionally skipped.

## Impact

- Git ignore policy at the repository root and Unity project root.
- Tracked Python bytecode and Unity `Library/`, `Logs/`, `UserSettings/`, `Build/`, and `.DS_Store` files.
- The local server's static WebGL input: `UnityClient/Build/WebGL` will no longer be present in a fresh checkout until generated by the documented Unity build.
- No runtime APIs or application dependencies change.
